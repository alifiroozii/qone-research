# سامانه هوشمند خدمات پژوهشی Qone Research

سامانه جامع، فارسی و راست‌چین (RTL) برای مدیریت خدمات مشاوره و پشتیبانی پژوهشی؛ با سه پنل مستقل **مشتری**، **کارشناس** و **مدیر کل**، فرم ثبت درخواست چندمرحله‌ای، صدور پیش‌فاکتور، پرداخت آزمایشی، ارجاع به کارشناس، پیگیری مراحل، پیام‌رسان داخلی، اعلان‌ها و تیکت پشتیبانی.

> **این نسخه یک نمایش آزمایشی (Demo Mode) است.** بدون دیتابیس واقعی اجرا می‌شود؛ داده‌ها فقط در مرورگر شما (localStorage) ذخیره می‌شوند، بین دستگاه‌ها به اشتراک گذاشته نمی‌شوند و ورود آزمایشی هیچ امنیت احراز هویت واقعی ندارد. هیچ اطلاعات حساس واقعی وارد نکنید.

## نصب و اجرا

پیش‌نیاز: Node.js نسخه ۱۸ یا بالاتر.

```bash
# نصب وابستگی‌ها
npm install

# اجرای نسخه توسعه (http://localhost:3000)
npm run dev

# ساخت نسخه تولید
npm run build

# اجرای نسخه تولید
npm start
```

برای Build و اجرا به `DATABASE_URL` نیازی نیست — برنامه بدون دیتابیس واقعی اجرا می‌شود.

## حساب‌های نمایشی

رمز عبور همه حساب‌ها: `demo1234`

| نقش | نام کاربری | ایمیل |
|---|---|---|
| مدیر کل | `admin` | `admin@qoneresearch.com` |
| کارشناس | `expert` | `rezaei@qoneresearch.com` |
| مشتری | `client1` | `client1@example.com` |

در صفحه `/login` می‌توانید با **نام کاربری یا ایمیل** وارد شوید. همچنین از دکمه‌های «ورود به پنل…» بدون رمز، مستقیم با هر نقش وارد شوید.
در هدر هر پنل دکمه **بازنشانی داده** داده‌های نمایشی را به حالت اولیه برمی‌گرداند.

## سناریوی کامل قابل آزمایش

تمام این مراحل در یک مرورگر، با همان داده‌های مشترک localStorage قابل انجام است:

1. با حساب **مشتری** وارد شوید.
2. از «ثبت درخواست جدید» خدمت انتخاب کنید، فرم را تکمیل و فایل اضافه کنید؛ در مرحله بازبینی برگردید و ویرایش کنید، سپس «ثبت نهایی». کد پیگیری یکتا دریافت می‌کنید.
3. با **مدیر** وارد شوید: سفارش جدید در «سفارش‌های جدید» است. وارد جزئیات شوید و «صدور پیش‌فاکتور» را با ردیف‌های دلخواه انجام دهید.
4. با **مشتری**: پیش‌فاکتور را «تأیید» کنید، سپس «پرداخت آزمایشی» انجام دهید.
5. با **مدیر**: «ارجاع به کارشناس» را انجام دهید.
6. با **کارشناس**: پروژه در «پروژه‌های ارجاع‌شده» است؛ مراحل را «شروع» و «تکمیل» کنید و پیام ارسال کنید.
7. با **مشتری**: پیشرفت مراحل، پیام و فایل‌ها را ببینید.
8. با **مدیر**: «تأیید و تکمیل سفارش».
9. داشبورد هر سه نقش و نمودارهای مدیر به‌روزرسانی می‌شوند.

## کدام بخش‌ها آزمایشی‌اند

- ذخیره‌سازی: فقط مرورگر (localStorage) — جایگزین بک‌اند نیست.
- احراز هویت: بدون هش رمز، نشست امن یا محدودسازی — فقط برای نمایش نقش‌ها.
- پرداخت: دکمه «پرداخت آزمایشی» یک تراکنش نمونه ثبت می‌کند؛ رسید واقعی نیست.
- فایل‌ها: فقط متادیتا (نام/حجم) نگهداری می‌شود؛ آپلود واقعی انجام نمی‌شود.
- اعلان/پیام/تیکت: فقط داخلی و نمایشی؛ پیامک/ایمیل واقعی ارسال نمی‌شود.

## اتصال دیتابیس واقعی (PostgreSQL + Prisma)

ساختار کامل مدل‌ها در `prisma/schema.prisma` طراحی شده است. مراحل اتصال:

1. فایل `.env` را از روی `.env.example` بسازید و `DATABASE_URL` را مقداردهی کنید:
   ```bash
   cp .env.example .env
   ```
2. میگریشن را اعمال کنید:
   ```bash
   npx prisma migrate dev --name init
   ```
3. در `src/server/providers/repository.ts` به‌جای `DemoRepository`، یک پیاده‌سازی Prisma-backed با همان متدها قرار دهید؛ چون همه صفحات فقط از `getRepository()` / `useData()` استفاده می‌کنند، رابط کاربری بدون تغییر عمده کار می‌کند.
4. احراز هویت واقعی (هش رمز، نشست امن، محدودسازی ورود) و کنترل دسترسی سمت سرور را اضافه کنید — پنهان کردن منو کافی نیست.

## اتصال پرداخت واقعی (زرین‌پال / آی‌دی‌پی)

- در `DemoRepository.demoPay()` فقط یک تراکنش نمایشی ثبت می‌شود. برای پرداخت واقعی یک Provider سروری بسازید:
  - ساخت درخواست پرداخت و هدایت به درگاه
  - دریافت Callback و **تأیید تراکنش در سمت سرور** (هرگز فقط بر اساس پاسخ مرورگر)
  - ثبت شناسه تراکنش با Idempotency، مدیریت تراکنش ناموفق و گزارش مالی
- کلیدهای درگاه را در Environment Variables سرور قرار دهید (`.env.example` را ببینید).

## استقرار در GitHub و Vercel

```bash
git init
git add .
git commit -m "Qone Research demo"
git remote add origin <repo-url>
git push -u origin main
```

سپس در [Vercel](https://vercel.com) با Import کردن ریپو، پروژه Next.js را Deploy کنید. تنظیمات خاصی لازم نیست و `DATABASE_URL` برای نسخه نمایشی ضروری نیست (روی Vercel از فایل‌سیستم موقت به‌عنوان دیتابیس استفاده نکنید — داده‌های نمونه در مرورگر مدیریت می‌شوند).

## معماری

```
src/
  app/
    (marketing)/        # خانه، خدمات، راهنما، درباره، تماس، FAQ، حریم خصوصی، قوانین
    (auth)/             # ورود و ثبت‌نام
    panel/
      client/           # داشبورد، ثبت درخواست، سفارش‌ها، پیام‌ها، فایل‌ها، پیش‌فاکتورها، پرداخت‌ها، اعلان‌ها، پشتیبانی، پروفایل
      expert/           # داشبورد، پروژه‌ها، وظایف، زمان‌بندی، پیام‌ها، فایل‌ها، تحویل‌ها، اعلان‌ها، پروفایل
      admin/            # داشبورد با نمودارها، سفارش‌ها، مشتریان، کارشناسان، پیش‌فاکتورها، پرداخت‌ها، گزارش‌ها، خدمات، پیام‌ها، پشتیبانی، اعلان‌ها، تنظیمات
  components/
    ui/                 # کامپوننت‌های پایه راست‌چین
    branding/           # لوگوی سه‌مفهومی SVG
    layout/             # هدر/فوتر مارکتینگ، پوسته پنل‌ها، سایدبار، تاپ‌بار، گارد نقش
    dashboard/          # کارت آماری، empty-state، اعلان‌ها، پروفایل
    marketing/          # هیرو و بخش‌های خانه
    orders/             # تب‌های جزئیات سفارش، فرم چندمرحله‌ای، دیالوگ پیش‌فاکتور/ارجاع
    charts/             # نمودارهای Recharts (فارسی/RTL)
    tables/             # جدول مدیریت سفارش‌ها
    settings/           # تنظیمات برند
  server/
    repositories/       # DemoRepository — لایه داده قابل جایگزینی
    providers/          # factory مخزن (نقطه اتصال Prisma آینده)
    services/           # توابع تحلیلی داشبورد
  data/mock/            # داده‌های نمونه فارسی (۱ مدیر، ۳ کارشناس، ۸ مشتری، ۲۰ سفارش)
  lib/                  # کانتکست‌ها (auth/brand/data)، فرمت‌کننده‌های فارسی
  types/                # تایپ‌های دامنه + AppDatabase
prisma/
  schema.prisma         # مدل‌های آینده PostgreSQL
```

فناوری‌ها: Next.js 15 (App Router) • React 19 • TypeScript Strict • Tailwind CSS • Radix UI • Framer Motion • React Hook Form + Zod • Recharts • Prisma • Vazirmatn (Self-Hosted) • کاملاً فارسی و RTL.
